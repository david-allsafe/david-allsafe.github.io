~$ cat summary.txt

Hands-on analysis lab of DarkComet RAT v5.3, reproducing the full attack cycle: C2 infrastructure setup, payload generation, delivery, established connection, remote control with data exfiltration, and remote shutdown of the compromised system.

Fully isolated environment — two Windows 7 SP1 VMs on an internal VirtualBox network with no internet access ("labrede", 192.168.100.0/24) — no distribution of the payload outside the lab.

~$ cat phases.log

  1. 1. Server setup — DarkComet listening on port 1604 (Listening, UPnP enabled)
  2. 2. Stub generation — minimal payload generated as update.exe, IP corrected to 192.168.100.1, persistence enabled, disguised as a legitimate update
  3. 3. Victim preparation — transferred via a VirtualBox shared folder (stands in for a real vector: phishing/USB/drive-by), temporary Defender exception on the host
  4. 4. Delivery and execution — victim runs the payload; stub connects to the C2 on port 1604
  5. 5. Connection established — victim appears on the panel with IP, OS, RAM, language and real-time latency
  6. 6. Remote control and exfiltration — active Remote Desktop, System Info collection (OS, MAC, SysDir, uptime)
  7. 7. Remote shutdown — victim machine shut down on the attacker's command
